# CHEATSHEET: 報告テンプレ集

## 報告は3段階（目的が違う。混ぜない）
| 段階 | いつ | 原因は必要? |
|---|---|---|
| 一次報告 | 検知から十数分以内 | 不要（分からなくていい） |
| 経過報告 | 状況変化時 / 定時 | 調査中でよい |
| 最終報告(RCA) | 収束後 | 必須 |

## 一次報告（速さが価値。原因は要らない）
【一次報告】<現象> / <発生時刻 JST>
■影響: <誰が・何ができないか>
■現状: <確認済みの事実 / 実施中の対応>
■原因: 調査中
■次報告: <HH:MM JST までに>

## 最終報告 / RCA
【最終報告】<件名>
■発生時刻: <YYYY-MM-DD HH:MM JST>
■復旧時刻: <同>（影響時間: N分）
■影響: <誰が何をできなかったか。件数・規模>
■時系列:
  HH:MM 検知（検知経路）
  HH:MM 一次切り分け（どの層をどう切ったか）
  HH:MM 原因特定
  HH:MM 対処実施
  HH:MM 復旧確認（判定根拠）
■原因: 直接原因 / 根本原因（分けて書く）
■対処: <実施内容>
■恒久対策: <いつまでに誰が>
■残課題: <未対応>

## 手順書 / runbook
■目的 / ■前提条件 / ■影響範囲
■手順（1コマンド1行 + 期待結果）
■確認方法（成功の判定基準）
■ロールバック手順
■完了条件
※ロールバックと完了条件が無い手順書は承認されない

## 日報
■本日の作業（完了/未完を明示）
■気づき・学び
■詰まった点と解決 ← ここが一番評価される
■未完了・持ち越し
■確認したいこと

## 書き方の鉄則
- 時刻には必ずTZ（14:32 JST）。ログはUTC、会話はJST
- 影響は「誰が何をできないか」で書く（× サーバが落ちた / ○ 全ユーザーがログイン不可）
- 次報告の時刻を自分から宣言する（催促が止まる）
- 事実「〜を確認」/ 推測「〜と思われる」/ 未確認「〜は未確認」を書き分ける
- 「未確認です」と書けるのがプロ。空欄や推測で埋めない
- 直接原因と根本原因を分ける。恒久対策は根本原因に打つ

## NG例
- 推測を事実として断定（「〜が原因です」← 未確定なら書かない）
- 影響範囲が無い（読む側が判断できない）
- 次アクション/期限が無い（放置に見える）
- 時刻にTZが無い / 「先ほど」「さっき」で書く
